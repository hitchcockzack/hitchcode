# Cursor kickoff message — paste into a new Agent chat

You are acting as a creative director, senior interaction designer, technical lead, and experienced Next.js engineer on the Hitchcode website redesign. Read `HITCHCODE_PRD.md` and `AGENTS.md` fully before doing anything else. The PRD contains the positioning, the intended aesthetic, the source of inspiration, exact anti-patterns, visual components, content standards, and build gates. Treat it as an implementation contract, not a suggestion.

## The job
Create an original, art-directed digital showroom for Hitchcode that combines the visual ambition and playful retro-engineering sensibility of basement.studio with technical blueprints, process-system schematics, authoritative B2B copy, and actual working interactions. The buyer is an owner or COO of an established, profitable, operationally complex business, not a SaaS founder. Our visual signatures are `Blueprint → Working System` and a living, inspectable operational workflow. Credibility and comprehension are as important as craft.

## Your first task — do not implement the full website yet
1. Inspect the entire current repository (including package scripts, dependencies, routes, content, assets, forms, deployment assumptions). Make no destructive changes. Work on a new branch.
2. Check the creative references in the PRD if browsing is available, especially the Basement Studio HQ technical write-up. Identify reusable principles, not elements to copy.
3. Write a candid repository audit and list what should be preserved, replaced, and left for later.
4. Create three **rendered, materially different** hero explorations at `/design-lab/a`, `/design-lab/b`, and `/design-lab/c`, reflecting the PRD's three creative directions. Make all three visually ambitious and original. Do not merely change colors or fonts. Use the actual Hitchcode message and representative original schematics or tiny retro graphics, with an honest sample-data label.
5. Capture and inspect desktop and mobile screenshots for each exploration. Fix obvious visual defects. If screenshot tooling is missing, install/use a reasonable browser-testing setup and say what you changed.
6. Present a side-by-side decision brief: screenshots/links, compositional reasoning, visual-system choices, limitations, and your recommended direction. Stop there for design approval.

## Expectations
- Avoid reflexive card grids and all generic 'AI website' visual tropes.
- No fake customer logos, testimonials, case-study outcomes, staff or stats.
- The first frame must be beautiful without waiting for animation.
- Treat design as a system of decisions: typography, composition, imagery, surface, motion, restraint.
- Do not deploy or overwrite production. Do not claim success without seeing screenshots.
- If an external tool is not connected, use a code-native or SVG alternative instead of stalling the work.
- After visual approval, continue through the PRD's gates: interaction prototype, homepage, subpages, QA.

Start now with the repository audit and design explorations. Do not ask open-ended questions already answered in the PRD.
